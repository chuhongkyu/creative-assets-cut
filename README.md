# Creative Asset Studio

영상이나 이미지를 넣으면 **App Store**·**YouTube**·**Instagram** 소재 규격으로 잘라 내보내는 웹 도구.

Sticker Slime 광고 소재를 만들려고 시작했지만 게임과 무관하게 동작한다.

```bash
npm install
npm run dev     # http://localhost:3000
```

## 서버가 없다

**이 프로젝트에는 백엔드가 없다.** API 라우트도, 서버 함수도 없다.
영상 디코딩·크롭·재인코딩이 전부 브라우저 안에서 일어나고 파일이 밖으로 나가지 않는다.

`next.config.mjs`가 `output: "export"`라 정적 파일로만 빌드된다. Vercel은 호스팅만 한다.

### 왜 WebCodecs인가

브라우저에서 mp4를 만드는 방법은 셋인데 하나만 쓸 만하다.

| 방법 | 결과 | 왜 안 썼나 |
|---|---|---|
| **WebCodecs + mp4-muxer** | **mp4** | 쓰고 있는 것. 브라우저 하드웨어 코덱을 직접 부른다 |
| MediaRecorder | webm | Chrome이 webm만 내놓는다. Apple은 mp4/mov를 요구한다 |
| ffmpeg.wasm | mp4 | 30MB 다운로드 + SharedArrayBuffer용 COOP/COEP 헤더가 필요하다 |

WebCodecs는 **Chrome·Edge·Safari 16.4+**에서 동작한다. 지원하지 않는 브라우저면 경고가 뜨고 영상 내보내기만 막힌다.

### 코덱 레벨 주의

H.264 코덱 문자열 끝 두 자리가 **레벨**이고, 레벨이 해상도 상한을 정한다.
`avc1.42001f`(Baseline 3.1)의 상한은 **1280×720**이라 App Store 규격은 전부 이를 넘는다.
헤더(3840×1646)는 24,720 매크로블록이라 **레벨 5.1 이상**이 필요하다. 후보 목록의 첫 항목인 5.2가 쓰인다.

레벨이 모자라면 `configure()`는 통과하고 **첫 `encode()`에서 인코더가 닫히면서**
`Cannot call 'encode' on a closed codec` 만 보인다. 진짜 원인이 가려지는 셈이다.

그래서 넉넉한 레벨부터 `VideoEncoder.isConfigSupported()`로 물어보고 실제로 받아주는 것을 쓴다.
에러가 나면 해상도와 코덱을 메시지에 붙여 돌려준다.

## 규격

`src/lib/presets.ts` 한 곳에 모여 있다. 규격이 바뀌면 여기만 고치면 된다.

규격은 **플랫폼별로 묶여 있다.** 주의사항이 플랫폼마다 다르기 때문이다 —
4+ 규칙을 목록 맨 아래에 한 번만 두면 YouTube 규격에도 걸리는 것처럼 보인다.

### App Store

| 자리 | 크기 | 비고 |
|---|---|---|
| Product page header | 3840 × 1646 | 제품 페이지 최상단 |
| Search results | 1920 × 1280 | 검색 결과. 3:2 |
| App preview (세로) | 886 × 1920 | 제품 페이지에서 재생되는 영상 |

#### 앱 미리보기와 앱 스크린샷은 다르다

| | 무엇 | 크기 |
|---|---|---|
| **앱 미리보기** | **영상** | 1920 × 886, 886 × 1920 |
| 앱 스크린샷 | 정지 이미지 | 2556 × 1179, 1179 × 2556, 2622 × 1206, 1206 × 2622 |

이름이 비슷해서 섞이기 쉬운데 **앱 미리보기만 영상이다.** 제품 페이지에서 재생되는 그것이다.
스크린샷 쪽 숫자는 iPhone 실제 화면 해상도라 크기가 전혀 다르다.

세로형 **886 × 1920**만 넣어뒀다. 가로형(1920 × 886)이 필요하면 `presets.ts`에 한 줄이다.
스크린샷은 규격으로 넣지 않았다 — 이미지 한 장을 올리면 jpg로 나오므로 넣는 것 자체는 되지만,
필요해지면 그때 넣는 편이 낫다.

#### 이 숫자의 출처

**Apple 디자인 템플릿(Figma 등)의 캔버스 치수는 틀렸다.** 거기서 읽은 값으로 한동안 만들었는데
실제 규격과 맞는 것이 하나도 없었다.

믿을 것은 **Apple이 쓰는 소재 파일 이름**이다. `header_3840x1646_15s.mp4` 처럼
자리와 해상도가 이름에 그대로 박혀 있다. 규격이 의심스러우면 템플릿을 다시 재지 말고
그 이름을 찾는 편이 빠르다.

뒤의 `15s`는 **그 파일 하나의 길이일 뿐 규칙이 아니다.** 헤더에 정해진 길이는 없다.

Universal(1402×962)도 템플릿에서 나온 값이라 뺐다. 그런 자리가 실제로 있는지 파일 이름으로
확인되면 그때 다시 넣는다.

#### 길이

헤더에 정해진 길이는 없다. 그래서 앱도 길이를 검사하지 않는다.

다만 **너무 짧으면 쓸 수 없었다.** 3초는 안 됐고 10초는 괜찮았다. Apple이 밝힌 하한은 없지만
최소 길이가 걸려 있는 것으로 보인다. 짧게 가고 싶어도 **10초쯤**에서 잡는 게 안전하다.

두 자리 모두 **영상과 이미지를 둘 다** 받는다. 규격마다 쓰고 싶은 소재가 다르기 때문에(헤더는 분위기, 검색은 한눈에 알아볼 장면) **자리별로 따로 올린다.**

### YouTube

| 자리 | 크기 | 비고 |
|---|---|---|
| 동영상 | 1920 × 1080 | 16:9 / 1080p |
| Shorts | 1080 × 1920 | 9:16 세로 |
| 썸네일 | 1280 × 720 | 이미지 한 장 → jpg. 2MB 이하 |

App Store와 달리 이쪽은 **규격이 아니라 권장값이다.** 벗어나도 거부되지 않고 YouTube가 알아서
변환한다. 그래도 권장값으로 올리면 재변환을 한 번 덜 거친다.

가로는 **1080p만 넣어뒀다.** 720p(1280×720)와 4K(3840×2160)도 받지만, 받는 해상도를 모두
늘어놓으면 고를 때 헷갈리기만 한다. 4K 소재가 생기면 `presets.ts`에 한 줄 넣으면 된다.

Shorts 길이는 검사하지 않는다. 헤더와 같은 이유다 — 걸리는 상한이 바뀌어 왔고, 앱이 틀린 값으로
막아서면 손해다.

내보내는 형식이 이미 **MP4 / H.264 영상 / AAC 소리**라 권장 형식과 그대로 맞는다.

프레임레이트는 YouTube가 **원본 그대로**를 권한다. 그래서 규격에 박지 않고 편집 화면에서
`24 / 30 / 60` 중에 고르게 뒀다. 원본이 60이면 60으로 내보내면 된다.

썸네일의 **2MB 제한은 검사하지 않는다.** 1280×720 jpg는 품질 0.92로도 한참 밑이고,
만든 파일 용량은 내보내기 버튼 옆에 늘 표시된다.

### Instagram

| 자리 | 크기 | 비고 |
|---|---|---|
| Reels | 1080 × 1920 | 9:16 세로 |

**치수가 Shorts와 똑같다.** 그래도 자리를 따로 둔다. 이 앱은 조각과 오버레이를 규격 단위로
들고 있어서, 하나로 합치면 두 곳에 같은 편집본만 내보낼 수 있다. 따로 두면 같은 원본으로
릴스용과 Shorts용을 다르게 자를 수 있다. **숫자가 겹친다고 합치지 말 것** — 겹치는 것은 치수뿐이다.

## 세로 규격

Shorts, Reels, App preview(세로) 셋이 세로 규격이다.

### 미리보기 상자가 높아진다

세로 규격에서는 상자 높이가 440에서 **660px**이 된다. 상자는 가로로 누워 있어서 세로 규격을
그대로 넣으면 틀이 193×343까지 쪼그라든다. 가로 소재를 세로로 자르는 작업은 어디를 버릴지
정확히 봐야 하는데 그 크기로는 할 수가 없다. 세로일 때만 늘리므로 가로 규격의 미리보기는 그대로다.

### 가로 소재는 위아래가 남는다

남는 자리는 흐린 배경으로 채워지지만, 그대로 두는 것보다 영상을 위나 아래로 몰고
**빈 쪽에 글자를 얹는** 편이 낫다. 끌어서 한쪽 끝까지 붙일 수 있다.

### 숏폼은 가장자리를 앱 UI가 덮는다

릴스도 Shorts도 위에는 계정과 설명이, 아래와 오른쪽에는 버튼이 올라온다.
거기 글자를 놓으면 가려진다. 해당하는 자리를 열면 편집 화면에 주의 문구가 뜬다.

**세로라고 다 해당하지는 않는다.** App preview도 세로지만 재생 화면 위에 아무것도 올라오지
않는다. 그래서 비율로 판단하지 않고 자리마다 `appChrome`으로 적어둔다. 없는 제약을 지키게
만들면 쓸 수 있는 자리를 괜히 비우게 된다.

**덮이는 범위를 픽셀로 적어두지 않았다.** 앱 업데이트마다 달라지는 값이고, 틀린 수치를
박아두는 것이 바로 Figma 템플릿에서 당한 일이다. 글자와 로고는 가운데로 모으고,
올리기 전에 실제 앱에서 확인하는 편이 낫다.

## 화면 구성

**규격 목록** — 규격이 각자의 비율 모양으로 나열된다. 누르면 그 규격의 편집 화면으로 들어간다.
모달이 아니라 화면 자체가 바뀐다. 타임라인과 미리보기를 같이 봐야 하는 작업이라 좁은 창에 담기지 않는다.

**편집 화면** — 위에서부터 미리보기 틀, 재생 막대, 타임라인.

## 이어 붙이기

파일을 여러 개 올리면 **올린 순서대로 이어 붙여 하나의 mp4**가 된다. 이미지와 영상을 섞어도 된다 —
이미지는 정해진 시간만큼 멈춰 있는 구간이 된다. 이미지 **한 장만** 올리면 jpg로 나온다.

타임라인에서:

- **끌어서 순서를 바꾼다** (`@dnd-kit`)
- **양쪽 끝을 끌어 구간을 잡는다.** 조각의 폭이 곧 길이다.
  영상은 **통째로** 들어가고, 필요한 만큼만 남기면 된다. 이미지는 길이가 없으니 2초로 들어가는데,
  오른쪽 끝을 끌어 **최대 30초까지** 늘릴 수 있다 — 한 장을 화면에 오래 세워두고 싶을 때 쓴다
  - **오른쪽**은 끝 지점만 바꾼다
  - **왼쪽**은 시작 지점을 옮기면서 길이를 같이 줄여, **끝나는 장면은 그대로** 둔다.
    왼쪽을 끌었는데 뒷부분까지 따라 움직이면 앞뒤를 번갈아 맞춰야 해서 못 쓴다
  - 시작 지점이 0이 아니면 조각에 `3.0s~` 처럼 표시된다
- 조각을 누르면 미리보기가 그 조각으로 바뀌고, 위치를 잡을 수 있다
- 빈 곳을 누르면 그 시각으로 재생 머리가 간다

인코더는 조각마다 새로 만들지 않고 하나로 쭉 간다. 그래야 이음매 없이 한 영상이 된다.

## 전환

조각이 **검정에서 들어오고 검정으로 나간다.** 내보내기 옆의 `페이드 인` / `페이드 아웃`에서
각각 `없음 / 0.3초 / 0.5초 / 1초`를 고른다.

**기본은 둘 다 없음이다.** 전환은 넣기로 정한 사람이 넣는 것이지, 모르는 사이에 끼어 있으면 안 된다.

**들어올 때와 나갈 때가 따로 논다.** 하나로 묶어두면 '들어올 때만 페이드'를 만들 수 없다 —
검정에서 열리되 끝은 딱 잘라 다음으로 넘기는 구성이 그렇다. 한쪽만 켜면 반대쪽은 하드컷이다.

맨 앞 조각은 검정에서 열리고 맨 뒤 조각은 검정으로 닫히므로, 소재 전체의 처음과 끝도 같이 정리된다.

**겹쳐 섞지(크로스페이드) 않고 검정을 거친다.** 겹치려면 한 프레임에 영상 두 개를 동시에
원하는 시각으로 맞춰 놓아야 하는데, 내보내기는 조각을 하나씩 순서대로 seek하며 돈다.
거기에 두 번째 디코더를 끼우면 구조가 통째로 바뀐다. 검정을 거치는 쪽은 한 번에 한 조각만
있으면 되고, 미리보기와 내보내기가 같은 식을 쓴다.

둘을 합친 길이가 조각보다 길면 **같은 비율로 줄인다.** 안 그러면 들어오는 구간과 나가는 구간이
겹쳐서 그 조각은 한 번도 제 밝기에 닿지 못한다. 한쪽만 켜져 있으면 조각 전체를 다 써도 되므로
절반으로 묶지 않는다 — 0.5초 조각에 1초짜리 페이드 인만 걸면 조각 내내 밝아진다.

검정은 **글자 위에도 덮인다.** 장면만 어두워지고 그 위의 로고가 밝게 남으면 어색하다.

가감속은 넣지 않았다. 위치가 움직이는 것과 달리 밝기는 선형이 눈에 고르다.

**전환도 재생해야 보인다.** 편집 화면은 재생 머리 위치의 한 장면을 제 밝기로 그린다 —
위치를 잡는 동안 화면이 어두우면 곤란하다.

## 재생

재생 버튼은 **이어 붙인 전체**를 재생한다. 조각 하나만 보려면 그 조각을 고르고 재생 머리를 그 구간에 두면 된다.

영상 구간은 매 프레임 seek을 걸지 않고 element를 그냥 재생시킨다. seek을 반복하면 디코더가 따라오지 못해
뚝뚝 끊긴다. 조각이 바뀌는 순간에만 앞엣것을 멈추고 다음 것을 제자리에서 재생한다.

멈춰 있을 때는 정확한 프레임을 보여주려고 seek으로 맞춘다.

**소리가 난다.** 재생 버튼이 사용자 조작이라 자동재생 정책에 걸리지 않는다. 멈추면 다시 음소거해서,
위치를 잡느라 seek할 때 소리가 새어 나오지 않게 한다. 재생 막대의 스피커 버튼으로 끌 수 있다.

내보낸 mp4에도 **소리가 담긴다.** 내보내기 옆의 `소리 담기`로 끌 수 있다.

video 엘리먼트에서는 디코딩된 오디오를 꺼낼 수 없어서, 원본 파일을 다시 읽어 `decodeAudioData`로 푼 뒤
`OfflineAudioContext`에 제자리에 꽂아 한 번에 렌더한다. 샘플레이트가 다른 소스가 섞여 있어도
OfflineAudioContext가 맞춰준다. 이미지 구간은 아무것도 꽂지 않으므로 그만큼 무음이 된다.

소리가 하나도 없으면 **오디오 트랙 자체를 만들지 않는다.** 빈 트랙이 붙은 mp4는 재생기에 따라 말썽을 일으킨다.

## 위치 잡기

미리보기 틀 안에서 **끌어서 옮긴다.** 틀은 가운데 고정이고 원본이 그 아래에서 움직인다.
**틀 밖도 보인다** — 어두운 바깥쪽이 잘려 나갈 부분이라, 무엇을 버리는지 보면서 맞출 수 있다.

**크기** 슬라이더가 확대·축소다. `1.00×`가 규격을 꼭 채우는 배율이고, 그보다 줄이면 여백이 생긴다.
여백은 단색 띠 대신 **원본을 흐리게 깔아** 채운다. 띠는 광고에서 눈에 거슬린다.

위치와 배율은 **조각마다 따로** 기억한다. 영상 둘과 이미지 하나를 이어 붙였다면 셋 다 다르게 잡는다.

조각을 고르는 것과 재생 머리가 **같이 움직인다.** 타임라인에서 조각을 누르면 재생 머리가 그 조각으로 가고,
재생 머리를 옮기면 그 자리의 조각이 골라진다. 멈춰 있을 때 미리보기에 나오는 것은 '고른 조각'이라,
둘이 따로 놀면 이미지 구간에 재생 머리를 올려놔도 화면에는 앞 영상이 남아 있었다.

**오버레이를 고른 상태에서는 미리보기를 끌면 오버레이가 움직인다.** 조각이 아니다.
지금 무엇을 끌고 있는지 미리보기 아래에 적히고, `조각 옮기기로` 버튼으로 돌아온다.

### 1.00×에서 한 축이 잠겨 있던 문제

`coverScale`이 '규격을 꼭 채우는 배율'이라 **1.00×에서는 정의상 한 변이 규격과 똑같아진다.**
빈 가장자리를 막는 식만 쓰면 그 축의 여유가 정확히 0이 된다 — 기본값에서 늘 한 축이 잠겨 있었다는 뜻이고,
9:16 소재를 9:16 규격에 넣으면 두 축 다 잠겼다. 먼저 배율을 건드려야 한다는 걸 알 길이 없어
그냥 고장난 것처럼 보였다.

그래서 **규격 절반**만큼은 언제나 움직이도록 바닥을 깔았다. 원본의 가운데가 규격 안에 있는 한 움직인다.
2× 이상으로 확대해 둔 상태에서는 예전처럼 빈틈이 생기지 않는다 — 차이의 절반이 더 커지기 때문이다.
그 사이에서 생기는 빈 자리는 흐린 배경이 채우므로 띠처럼 보이지 않는다.

### 세로 영상을 가로 규격에 넣을 때

App Store 규격은 전부 가로인데 게임이 세로면 그대로는 들어가지 않는다.
`크기`를 1.00× 아래로 내려 세로 화면 전체를 담고, **한쪽으로 몰아 남는 쪽에 제목이나 로고를 얹는다.**

배율 하한은 **0.2×**다. 예전 0.4×로는 1080×1920을 3840×1646 안에 통째로 담을 수 없었다 —
그 조합에 0.24×가 필요한데 슬라이더가 0.4에서 멈췄다.

규격보다 작을 때도 한쪽 끝에 붙을 때까지 끌 수 있다. 가운데로 고정해두면 이 구성을 만들 수 없다.

## 위에 얹기

**글자**와 **이미지**를 영상 위에 올릴 수 있다. 로고나 제목처럼 소재 전체에 걸치는 것들이다.

- 목록에서 고르면 **미리보기에서 끌어 옮긴다.** 고른 상태에서는 조각 대신 오버레이가 움직인다
- 크기·투명도, 글자는 색과 줄바꿈까지
- **구간**은 타임라인 아래 전용 트랙에서 잡는다. 조각과 같은 눈금 위에 있어서
  어느 장면에 걸쳐 있는지 바로 보인다
  - 막대를 **끌면 통째로** 옮겨지고, **양 끝**을 끌면 시작·끝이 따로 움직인다
  - 기본은 전체 구간이다. 숫자로 정확히 넣고 싶으면 아래 입력칸을 쓴다

## 움직임

오버레이마다 **등장**과 **퇴장**을 따로 고른다.

| | |
|---|---|
| 없음 | 그냥 나타났다 사라진다 |
| 서서히 | 투명도만 |
| 아래서 위로 | 아래에서 올라오며 |
| 위에서 아래로 | 위에서 내려오며 |
| 커지며 | 작게 시작해 제자리 크기로 |

**속도**가 한 번의 움직임에 걸리는 시간이다.

위치가 움직이는 종류도 투명도를 같이 쓴다. 위치만 바뀌면 갑자기 튀어나온 것처럼 보인다.
가감속은 끝에서 느려지게 뒀다 — 선형이면 뚝뚝 끊겨 보인다.
들어오는 거리는 규격 높이에 비례하므로 어느 크기에서나 같은 느낌이 난다.

**움직임은 재생해야 보인다.** 편집 화면은 재생 머리 위치의 한 장면을 그리기 때문이다.

미리보기에는 **그 시각에 보이는 것만** 그린다. 다만 고른 것은 구간 밖이어도 보여준다 —
안 보이면 위치를 잡을 수가 없다.

위치와 크기는 규격 대비 **비율**로 저장한다. 미리보기는 작고 결과물은 크지만 같은 값으로 양쪽을 그려야
보이는 대로 나온다.

글자에는 그림자를 깐다. 광고 소재는 밝은 장면과 어두운 장면이 섞이기 마련이고, 어디에 와도 읽혀야 한다.

오버레이는 **조각이 아니라 규격 단위**다. 장면이 바뀌어도 로고는 그대로 있는 것이 보통이기 때문이다.

## 내보낸 파일 확인

App Store Connect가 "파일 크기가 유효하지 않습니다" 처럼 모호하게 거절할 때가 있다.
그 '크기'가 용량인지 해상도인지 알 수 없어서 직접 봐야 한다.

```bash
python3 inspect-mp4.py ~/Downloads/파일.mp4
```

```
용량     21.4 MB
길이     11.0초
코덱     avc1, mp4a
소리     있음
해상도   3840 x 1646
```

**앱 미리보기 상한은 500MB**지만, 자산 보관함에 올리는 창작 자산의 상한은 Apple이 공개하지 않았다.

비트레이트는 화소 수에 비례해 자동으로 잡는다. 만든 파일의 용량은 내보내기 버튼 옆에 표시된다.

## 원본 크기 주의

규격보다 작은 원본을 넣으면 확대되면서 흐려진다. 카드에 경고가 뜬다.

가장 큰 규격이 **3840 × 1646**이므로, 영상은 **긴 변 3840px 이상**(4K 폭)으로 녹화해두면 모든 규격을 축소만으로 처리할 수 있다. 1920×1080 같은 흔한 소스도 헤더에서는 두 배로 확대된다.

Unity 프로젝트라면 `com.unity.recorder`로 원하는 해상도를 직접 지정해 뽑을 수 있다.

## 소재 규정

App Store에 노출되는 소재는 **앱 등급과 무관하게 4+ 기준**을 만족해야 한다. 자산이 거부되는 가장 흔한 이유다.

Apple이 금지하는 것 중 게임에서 걸리기 쉬운 항목:

- 유혈·잔혹 묘사
- **사람이나 보는 사람을 향해 겨눈 무기**
- Editor's Choice, Apple Design Award 같은 Apple 선정 표식 (받지 않았다면 사용 금지)
- 검증 불가능한 수상 이력

자산 보관함(Asset Library)에 올리는 것과 실제로 노출되는 것은 다르다. 올린 뒤 **제품 페이지 헤더에 배정**하고, 지원하는 **모든 언어·지역에 현지화**해야 한다.

## 구조

```
src/
  app/page.tsx          규격을 세로로 쌓는다
  components/
    EditorView.tsx      규격 하나의 편집 화면 전체
    Stage.tsx           미리보기 틀. 끌어서 위치 잡기 + 재생 화면
    Timeline.tsx        조각 트랙. 순서 바꾸기 + 길이 조절
    OverlayPanel.tsx    위에 얹는 글자·이미지 목록과 설정
  hooks/
    usePlayback.ts      이어 붙인 전체 재생
  lib/
    presets.ts          규격 목록 ← 규격이 바뀌면 여기
    clips.ts            조각(이미지/영상) 만들기와 길이 계산
    playback.ts         타임라인 위치 계산과 그리기
    transitions.ts      조각 사이 페이드
    overlays.ts         위에 얹는 글자·이미지
    audio.ts            조각들의 소리를 모아 AAC로
    transform.ts        위치·배율 계산과 그리기. 미리보기·크롭 창·내보내기가 같은 함수를 쓴다
    exportImage.ts      캔버스 → jpg
    exportVideo.ts      조각들을 이어 WebCodecs → mp4
```

미리보기와 실제 내보내기가 **같은 `computePlacement`를 쓴다.** 보이는 것과 나오는 것이 어긋나지 않게 하려는 의도다.
