# Creative Asset Studio

영상이나 이미지를 넣으면 **App Store** 소재 규격으로 잘라 내보내는 웹 도구.

Sticker Slime 광고 소재를 만들려고 시작했지만 게임과 무관하게 동작한다.

```bash
npm install
npm run dev     # http://localhost:3000
```

## 서버가 없다

**이 프로젝트에는 백엔드가 없다.** API 라우트도, 서버 함수도 없다.
영상 디코딩·크롭·재인코딩이 전부 브라우저 안에서 일어나고 파일이 밖으로 나가지 않는다.

`next.config.mjs`가 `output: "export"`라 정적 파일로만 빌드된다. Vercel은 호스팅만 한다.

### 왜 WebCodecs인가

브라우저에서 mp4를 만드는 방법은 셋인데 하나만 쓸 만하다.

| 방법 | 결과 | 왜 안 썼나 |
|---|---|---|
| **WebCodecs + mp4-muxer** | **mp4** | 쓰고 있는 것. 브라우저 하드웨어 코덱을 직접 부른다 |
| MediaRecorder | webm | Chrome이 webm만 내놓는다. Apple은 mp4/mov를 요구한다 |
| ffmpeg.wasm | mp4 | 30MB 다운로드 + SharedArrayBuffer용 COOP/COEP 헤더가 필요하다 |

WebCodecs는 **Chrome·Edge·Safari 16.4+**에서 동작한다. 지원하지 않는 브라우저면 경고가 뜨고 영상 내보내기만 막힌다.

### 코덱 레벨 주의

H.264 코덱 문자열 끝 두 자리가 **레벨**이고, 레벨이 해상도 상한을 정한다.
`avc1.42001f`(Baseline 3.1)의 상한은 **1280×720**이라 App Store 규격은 전부 이를 넘는다.

레벨이 모자라면 `configure()`는 통과하고 **첫 `encode()`에서 인코더가 닫히면서**
`Cannot call 'encode' on a closed codec` 만 보인다. 진짜 원인이 가려지는 셈이다.

그래서 넉넉한 레벨부터 `VideoEncoder.isConfigSupported()`로 물어보고 실제로 받아주는 것을 쓴다.
에러가 나면 해상도와 코덱을 메시지에 붙여 돌려준다.

## 규격

`src/lib/presets.ts` 한 곳에 모여 있다. 규격이 바뀌면 여기만 고치면 된다.

| 자리 | 크기 | 비고 |
|---|---|---|
| Universal | 1402 × 962 | 헤더와 검색 결과에 함께 쓴다. **하나만 만든다면 이것** |
| Product page header | 1646 × 661 | 제품 페이지 최상단 |
| 3:2 영상 | 1920 × 1280 | H.264 / MP4 / 30fps / 5~30초 |
| Search results | 2168 × 1030 | 검색 결과 |

세 자리 모두 **영상과 이미지를 둘 다** 받는다. 규격마다 쓰고 싶은 소재가 다르기 때문에(헤더는 분위기, 검색은 한눈에 알아볼 장면) **자리별로 따로 올린다.**

## 화면 구성

**규격 목록** — 세 규격이 각자의 비율 모양으로 나열된다. 누르면 그 규격의 편집 화면으로 들어간다.
모달이 아니라 화면 자체가 바뀐다. 타임라인과 미리보기를 같이 봐야 하는 작업이라 좁은 창에 담기지 않는다.

**편집 화면** — 위에서부터 미리보기 틀, 재생 막대, 타임라인.

## 이어 붙이기

파일을 여러 개 올리면 **올린 순서대로 이어 붙여 하나의 mp4**가 된다. 이미지와 영상을 섞어도 된다 —
이미지는 정해진 시간만큼 멈춰 있는 구간이 된다. 이미지 **한 장만** 올리면 jpg로 나온다.

타임라인에서:

- **끌어서 순서를 바꾼다** (`@dnd-kit`)
- **양쪽 끝을 끌어 구간을 잡는다.** 조각의 폭이 곧 길이다.
  영상은 **통째로** 들어가고, 필요한 만큼만 남기면 된다. 이미지는 길이가 없으니 2초로 들어간다
  - **오른쪽**은 끝 지점만 바꾼다
  - **왼쪽**은 시작 지점을 옮기면서 길이를 같이 줄여, **끝나는 장면은 그대로** 둔다.
    왼쪽을 끌었는데 뒷부분까지 따라 움직이면 앞뒤를 번갈아 맞춰야 해서 못 쓴다
  - 시작 지점이 0이 아니면 조각에 `3.0s~` 처럼 표시된다
- 조각을 누르면 미리보기가 그 조각으로 바뀌고, 위치를 잡을 수 있다
- 빈 곳을 누르면 그 시각으로 재생 머리가 간다

인코더는 조각마다 새로 만들지 않고 하나로 쭉 간다. 그래야 이음매 없이 한 영상이 된다.

## 재생

재생 버튼은 **이어 붙인 전체**를 재생한다. 조각 하나만 보려면 그 조각을 고르고 재생 머리를 그 구간에 두면 된다.

영상 구간은 매 프레임 seek을 걸지 않고 element를 그냥 재생시킨다. seek을 반복하면 디코더가 따라오지 못해
뚝뚝 끊긴다. 조각이 바뀌는 순간에만 앞엣것을 멈추고 다음 것을 제자리에서 재생한다.

멈춰 있을 때는 정확한 프레임을 보여주려고 seek으로 맞춘다.

**소리가 난다.** 재생 버튼이 사용자 조작이라 자동재생 정책에 걸리지 않는다. 멈추면 다시 음소거해서,
위치를 잡느라 seek할 때 소리가 새어 나오지 않게 한다. 재생 막대의 스피커 버튼으로 끌 수 있다.

내보낸 mp4에도 **소리가 담긴다.** 내보내기 옆의 `소리 담기`로 끌 수 있다.

video 엘리먼트에서는 디코딩된 오디오를 꺼낼 수 없어서, 원본 파일을 다시 읽어 `decodeAudioData`로 푼 뒤
`OfflineAudioContext`에 제자리에 꽂아 한 번에 렌더한다. 샘플레이트가 다른 소스가 섞여 있어도
OfflineAudioContext가 맞춰준다. 이미지 구간은 아무것도 꽂지 않으므로 그만큼 무음이 된다.

소리가 하나도 없으면 **오디오 트랙 자체를 만들지 않는다.** 빈 트랙이 붙은 mp4는 재생기에 따라 말썽을 일으킨다.

## 위치 잡기

미리보기 틀 안에서 **끌어서 옮긴다.** 틀은 가운데 고정이고 원본이 그 아래에서 움직인다.
**틀 밖도 보인다** — 어두운 바깥쪽이 잘려 나갈 부분이라, 무엇을 버리는지 보면서 맞출 수 있다.

**크기** 슬라이더가 확대·축소다. `1.00×`가 규격을 꼭 채우는 배율이고, 그보다 줄이면 여백이 생긴다.
여백은 단색 띠 대신 **원본을 흐리게 깔아** 채운다. 띠는 광고에서 눈에 거슬린다.

위치와 배율은 **조각마다 따로** 기억한다.

## 위에 얹기

**글자**와 **이미지**를 영상 위에 올릴 수 있다. 로고나 제목처럼 소재 전체에 걸치는 것들이다.

- 목록에서 고르면 **미리보기에서 끌어 옮긴다.** 고른 상태에서는 조각 대신 오버레이가 움직인다
- 크기·투명도, 글자는 색과 줄바꿈까지
- **구간**은 타임라인 아래 전용 트랙에서 잡는다. 조각과 같은 눈금 위에 있어서
  어느 장면에 걸쳐 있는지 바로 보인다
  - 막대를 **끌면 통째로** 옮겨지고, **양 끝**을 끌면 시작·끝이 따로 움직인다
  - 기본은 전체 구간이다. 숫자로 정확히 넣고 싶으면 아래 입력칸을 쓴다

미리보기에는 **그 시각에 보이는 것만** 그린다. 다만 고른 것은 구간 밖이어도 보여준다 —
안 보이면 위치를 잡을 수가 없다.

위치와 크기는 규격 대비 **비율**로 저장한다. 미리보기는 작고 결과물은 크지만 같은 값으로 양쪽을 그려야
보이는 대로 나온다.

글자에는 그림자를 깐다. 광고 소재는 밝은 장면과 어두운 장면이 섞이기 마련이고, 어디에 와도 읽혀야 한다.

오버레이는 **조각이 아니라 규격 단위**다. 장면이 바뀌어도 로고는 그대로 있는 것이 보통이기 때문이다.

## 내보낸 파일 확인

App Store Connect가 "파일 크기가 유효하지 않습니다" 처럼 모호하게 거절할 때가 있다.
그 '크기'가 용량인지 해상도인지 알 수 없어서 직접 봐야 한다.

```bash
python3 inspect-mp4.py ~/Downloads/파일.mp4
```

```
용량     21.4 MB
길이     11.0초
코덱     avc1, mp4a
소리     있음
해상도   1402 x 962
```

**앱 미리보기 상한은 500MB**지만, 자산 보관함에 올리는 창작 자산의 상한은 Apple이 공개하지 않았다.
실제로 그보다 훨씬 작은 파일이 "파일 크기가 유효하지 않습니다"로 거절된 적이 있다.

그래서 내보내기에 **최대 용량(MB)** 칸을 뒀다. 길이에 맞춰 비트레이트를 거꾸로 계산하므로,
거절당하면 숫자를 낮춰 다시 구우면 된다. 손으로 품질을 깎는 것보다 빠르다.
만든 파일의 실제 용량도 버튼 옆에 표시된다.

## 원본 크기 주의

규격보다 작은 원본을 넣으면 확대되면서 흐려진다. 카드에 경고가 뜬다.

가장 큰 규격이 **2168 × 1030**이므로, 영상은 **긴 변 2200px 이상**으로 녹화해두면 모든 규격을 축소만으로 처리할 수 있다. 1280×720 같은 소스는 세 규격 전부에서 확대된다.

Unity 프로젝트라면 `com.unity.recorder`로 원하는 해상도를 직접 지정해 뽑을 수 있다.

## 소재 규정

App Store에 노출되는 소재는 **앱 등급과 무관하게 4+ 기준**을 만족해야 한다. 자산이 거부되는 가장 흔한 이유다.

Apple이 금지하는 것 중 게임에서 걸리기 쉬운 항목:

- 유혈·잔혹 묘사
- **사람이나 보는 사람을 향해 겨눈 무기**
- Editor's Choice, Apple Design Award 같은 Apple 선정 표식 (받지 않았다면 사용 금지)
- 검증 불가능한 수상 이력

자산 보관함(Asset Library)에 올리는 것과 실제로 노출되는 것은 다르다. 올린 뒤 **제품 페이지 헤더에 배정**하고, 지원하는 **모든 언어·지역에 현지화**해야 한다.

## 구조

```
src/
  app/page.tsx          규격 세 개를 세로로 쌓는다
  components/
    EditorView.tsx      규격 하나의 편집 화면 전체
    Stage.tsx           미리보기 틀. 끌어서 위치 잡기 + 재생 화면
    Timeline.tsx        조각 트랙. 순서 바꾸기 + 길이 조절
    OverlayPanel.tsx    위에 얹는 글자·이미지 목록과 설정
  hooks/
    usePlayback.ts      이어 붙인 전체 재생
  lib/
    presets.ts          규격 목록 ← 규격이 바뀌면 여기
    clips.ts            조각(이미지/영상) 만들기와 길이 계산
    playback.ts         타임라인 위치 계산과 그리기
    overlays.ts         위에 얹는 글자·이미지
    audio.ts            조각들의 소리를 모아 AAC로
    transform.ts        위치·배율 계산과 그리기. 미리보기·크롭 창·내보내기가 같은 함수를 쓴다
    exportImage.ts      캔버스 → jpg
    exportVideo.ts      조각들을 이어 WebCodecs → mp4
```

미리보기와 실제 내보내기가 **같은 `computeDrawRect`를 쓴다.** 보이는 것과 나오는 것이 어긋나지 않게 하려는 의도다.
